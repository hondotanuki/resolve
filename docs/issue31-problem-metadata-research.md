# Issue #31 問題URLからの情報取得調査

調査日：2026-11-08。目的はAtCoder・OnlineMathContest（OMC）の問題URLから、タイトル・出典・コンテスト種別・問題区分を取得できるか確認すること。調査と方針の記録であり、機能が実装済みであることや、すべての問題の取得可否を保証するものではない。

## 採用方針と後続作業

- 個人利用を前提に、新規登録時のみ必要な情報を取得する。AtCoderはAtCoder Problemsの非公式データ、OMCは入力された問題ページのHTMLを使う。OMCの問題一覧用JSONは外部アプリ向けの条件が未確認のため採用しない。
- 取得元ごとにリクエストを直列化し、同一提供元へのリクエスト開始間隔を2秒以上とする。AtCoder Problemsの「1秒より長く」という要請に余裕を持たせた設定であり、OMCが2秒を許可・指定しているという意味ではない。OMCは1件の登録で必要なページだけを取得し、巡回しない。
- 取得したAtCoder Problemsの一覧データは新規登録のためにキャッシュし、毎回ダウンロードしない。24時間は更新間隔の検討例であり確定値ではない。データ更新遅延・対象なしのときに、いつ再取得できるかを含む具体的な更新方針は実装時に決める。登録済み問題を定期更新する意味ではない。
- 登録済みURLの再入力では外部へアクセスせず、既存の詳細を開く。問題詳細の表示・学習時も再取得しない。登録した情報は手動で編集できる。外部からの手動更新と手動編集値の上書き方針は後続で検討する。
- タイトル・出典・コンテスト種別・問題区分のいずれかが取得できない場合や、目標時間のない区分では登録しない。誤った情報を推測して補完しない。
- `403`・`429` などの制限や取得失敗を利用者に伝え、自動で繰り返しアクセスしない。`Retry-After` がある場合はその指示を尊重する。入力URLの許可ホストとリダイレクト先を確認する。
- タグは新規登録・外部取得の対象に含めない。固定候補からの手動タグ付けはM3で扱う。

取得元の変更・障害や利用条件の変更はあり得る。個人利用・低頻度という前提やHTTP 200のみで自動取得の利用許諾を保証するものではなく、各サービスの案内を確認し、制限が示された場合は従う。

## HTMLからの取得

### AtCoder

今回取得した3ページでは、HTMLの `title` が `A - Nigiri` のような形式で、`a.contest-title` にコンテスト名があった。問題見出しにも問題記号とタイトルが表示される。`arc233` のページは `AtCoder Regular Contest++ 233` であり、目標時間の対応ではユーザーの方針によりARCと同じRegularに分類する。

URL末尾だけで問題記号を判断しない。たとえば [ABC043のC問題](https://atcoder.jp/contests/abc043/tasks/arc059_a) のURL末尾は `arc059_a` だが、ページ上の問題記号は `C` である。[ARC059の問題一覧](https://atcoder.jp/contests/arc059/tasks) でも同じ問題はCとして表示される。

### OMC

今回取得した3ページでは、`h1#problem-title` に `OMCB087(B)` など、コンテスト名と問題記号を含む表示があった。HTMLの `title` は共通のサイト名であり、今回の例では問題情報の取得に使えない。URLの `/tasks/5454` などの数字だけから問題記号を判断しない。

OMCB087のコンテストページでは、`Begin Time` の直前に開始日時が表示されていることを確認した。表示のタイムゾーンは未確認のため、ユーザー判断により、実装ではページに表示された日付を変換せず開始日として扱う。自動テストには模擬HTMLを使用し、OMCへ通信しない。

これらは6サンプルからの観測であり、他の回・期間中のコンテスト・非公開問題・画面構造の変更後にも適用できるかは未検証。

## AtCoder Problemsの公開データ

[AtCoder ProblemsのAPI説明](https://github.com/kenkoooo/AtCoderProblems/blob/main/doc/api.md) は、データセットを非公式と明記し、アクセス間隔を1秒より長くするよう案内している。APIの変更・廃止もあり得る。

2026-11-08に `merged-problems.json` を1回取得し、AtCoderの3サンプルについて `id`・`contest_id`・`problem_index`・`name` を確認できた。取得サイズは約4.8MB。`arc059_a` の `problem_index` も `C` だった。

同じ日に `contest-problem.json` も取得し、`arc059_a` が `abc043` と `arc059` の両方に `C` として関連付くことを確認した。データの鮮度、全問題の網羅性、正式なスキーマ保証は未検証。

## OMCの問題一覧で使われるJSON取得先

追加調査で、[OMCの問題一覧](https://onlinemathcontest.com/problems)が読み込む公式JavaScriptに、`GET /api/problems/list` の呼び出しがあることを確認した。2026-11-08に `type=B` を指定して1回取得したところ、未ログインでHTTP 200のJSONが返り、`omcb087` のコンテスト情報と `5454`・`OMCB087(B)` が含まれていた。

これは**OMC自身の画面が使う取得先を観測した結果**であり、外部アプリ向けの正式な公開API・利用許諾・安定性・利用頻度の条件が確認できたことを意味しない。外部利用の可否や案内・仕様書の有無は未確認であり、運営への問い合わせ候補とする。すべての系列・問題が含まれるか、最新性・データ変更時の互換性も未確認。

## 重複とURLの扱い

- 同じコンテスト・同じ問題のURLに `?lang=en` など言語指定だけが加わった場合は、同じ登録対象として扱う。ABC482 Aは言語指定付きURLでもHTTP 200だった。すべてのパラメーターを無条件に除去しない。
- ユーザー判断：同じAtCoder問題がABCとARCの両方に出題された場合は、**コンテストごとに別の問題として登録する**。同じ `arc059_a` でもABC043 Cは20分、ARC059 Cは50分となる。
- したがって、AtCoderの問題IDだけを重複判定のキーとする案は採用しない。コンテストの文脈を含む同一性と、OMCの同一性の具体的な表現は実装時に決める。
- 架空のAtCoder問題URLと架空のOMC問題URLを各1件試したところ、いずれもHTTP 404だった。全ての失敗が404になるとは限らない。

## 取得方式の候補と残る検討

| 候補 | 利点 | 確認・検討事項 |
| --- | --- | --- |
| 各公式ページのHTML | 両サービスの6例で必要な表示を確認。入力URLと表示元が直接対応する | HTML変更・アクセス制限・利用条件への対応。文字列・問題記号の抽出と失敗時の検証 |
| AtCoder Problemsデータセット | AtCoderの3例で構造化データを確認。コンテストとの対応一覧もある | 非公式サービスへの依存、約4.8MBのデータ取得、更新遅延や対象漏れ、提供元のアクセス間隔 |
| OMCの問題一覧のJSON取得先 | OMC自身のページが利用し、OMCB087のサンプルを未ログインで取得できた | 外部利用の可否、仕様の公開・安定性、頻度・利用条件、ほかの系列での網羅性 |

上記の比較を踏まえ、当面はAtCoder ProblemsのデータセットとOMCのHTMLを使う。OMCのJSON取得先の外部利用条件は未確認。いずれも、公開ページを取得できたことや `robots.txt` の内容だけをもって、すべての自動取得が許可されると判断しない。

未着手・未確認：実サービス全形式での網羅性、旧形式・共通問題・未開催／非公開の問題、取得先の遅延・エラー・DOM変更への対応、OMC固有の同一性。情報を誤って補完せず、必要情報が取得できない場合は登録しない。

## 結果の扱い

このSpikeでは本番の取得処理やDB変更は行っていない。後続の問題区分・データモデルIssueとURL登録Issueで方針を実装する。共通問題では、コンテストごとの問題記号を取得データから正しく特定できるかをテストで確認し、特定できない場合は未対応とする。OMCの問題の同一性、対応するURL形式、タイトルの扱い、キャッシュの詳細はURL登録Issueで決める。
